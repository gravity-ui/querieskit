# AGENTS.md

Инструкция для агентов по структуре кода в `@gravity-ui/querieskit`.

## Три уровня публичного API

Библиотека организована по трём уровням абстракции. Каждый новый и существующий виджет должен следовать этой структуре:

```text
src/
  components/   — базовые атомарные компоненты
  modules/      — сборки из нескольких components в переиспользуемый сценарный блок
  widgets/      — готовые продуктовые виджеты
  types/        — публичные типы
  helpers/      — общие хелперы, не привязанные к конкретному виджету
  index.ts
```

### `src/components` — базовые компоненты

Малые компоненты, которые не управляют большим сценарием и не содержат сложного состояния/оркестрации.

Правило включения: компонент попадает в `src/components`, только если потребитель библиотеки может использовать его отдельно и у компонента есть стабильный props-контракт. Не выносить компонент сюда только ради единообразия.

Примеры: [`QueryStatusIcon`](src/components/QueriesHistory/HistoryRow/QueryStatusIcon.tsx:27), [`HistoryDuration`](src/components/QueriesHistory/HistoryRow/HistoryDuration.tsx).

Структура компонента:

```text
components/
  ComponentName/
    ComponentName.tsx
    ComponentName.scss
    index.ts
```

### `src/modules` — модули

Блоки, которые собирают несколько `components` и задают сценарий взаимодействия внутри одного виджета (поиск, список, строка со своей логикой selection/editing и т.д.).

Модуль обычно не предназначен для использования отдельно от своего виджета — это внутренняя единица сборки, но выделенная в отдельный публичный уровень для читаемости импортов и повторного использования между виджетами при необходимости.

Части модуля, у которых нет самостоятельного сценария использования (например, внутренний header строки, внутреннее меню), не выносятся в `components`, а остаются внутри модуля — либо рядом с основным файлом, либо в подпапке `internal/`.

Структура модуля:

```text
modules/
  ModuleName/
    ModuleName.tsx
    internal/
      InternalPart.tsx
    helpers/
      helperFn.ts
    index.ts
```

### `src/widgets` — виджеты

Законченные feature-блоки, которые можно поставить в приложение как цельный виджет. Виджет собирает `modules` и `components`, содержит собственный i18n и widget-level настройки.

Структура виджета:

```text
widgets/
  WidgetName/
    WidgetName.tsx
    i18n/
    index.ts
```

## Правила импортов между уровнями

- `widgets` импортируют `modules` и `components`.
- `modules` импортируют `components`.
- `components` не импортируют `modules` или `widgets`.

Нарушение этого порядка (например, импорт виджета внутри модуля) недопустимо — это ломает читаемость уровней абстракции.

## Нейминг

- `components` / `modules` / `widgets` — фиксированные названия уровней. Не использовать `blocks` (конфликтует с BEM-терминологией проекта, см. `bem-cn-lite`), не использовать `compositions` или `features` (менее привычны / не соответствуют смыслу сущностей).
- Каждая единица на любом уровне — это папка `PascalCase` с файлом реализации того же имени и обязательным `index.ts`, реэкспортирующим публичный API папки.

## Barrel-экспорты

- У каждого уровня (`components`, `modules`, `widgets`) должен быть свой `index.ts`, который явно реэкспортирует публичные единицы этого уровня. Не использовать самоссылающиеся или циклические конструкции вида `export * from '.'`.
- [`src/index.ts`](src/index.ts:1) — точка входа, реэкспортирует публичные части всех трёх уровней и публичные типы из `src/types`.

## Типы

Публичные типы, являющиеся частью props-контракта компонентов/модулей/виджетов, должны лежать в `src/types` и реэкспортироваться через `src/index.ts`, если они нужны потребителю библиотеки для типизации своих данных (например, `QueryHistoryRow`, `QueryHistoryItem`).

## Проверка при добавлении нового виджета

При добавлении нового виджета в библиотеку:

1. Определить, какие части — самостоятельные `components`, какие — `modules`, а что относится только к самому `widget`.
2. Не выносить внутренние детали в `components` без реального сценария отдельного использования.
3. Создать/обновить `index.ts` на каждом затронутом уровне.
4. Убедиться, что импорты идут только в одном направлении: `widgets → modules → components`.
5. Проверить сборку и storybook после изменений.

Подробный пример применения этих правил к существующему виджету `QueriesHistory` — см. [`plans/queries-history-structure.md`](plans/queries-history-structure.md).
